# Étude

**A LilyPond→MIDI engine and SwiftUI app that teaches software testing.**

Étude parses a practical subset of [LilyPond](https://lilypond.org) notation (the
plain-text score format used by the [Mutopia Project](https://www.mutopiaproject.org/)),
validates it against musical invariants, and emits standard **Type-1 MIDI** files. A thin
SwiftUI app browses a bundled corpus of public-domain classical pieces, builds them
on-device, plays them, and exports the `.mid` for GarageBand, games, and DAWs.

It is also, deliberately, a **course in testing architecture**. The pipeline is a pure,
UI-free Swift package (`EtudeKit`) so its tests run fast on any platform. Every layer
carries its own lesson: table-driven unit tests, hand-rolled property-based tests,
golden-file/snapshot tests, invariant validation, regression tests reconstructed from real
historical bugs, and XCUITest UI flows with the Page Object pattern.

> **Project policy: never ship a subtly wrong version.** A correct excerpt beats an
> incorrect whole. Where the engine cannot yet render a piece faithfully — today, Debussy's
> **Clair de Lune** — we mark it a *visible known issue* rather than disabling the test or
> shipping something that merely sounds plausible. See
> [`docs/adr/0003-known-issue-not-skip.md`](docs/adr/0003-known-issue-not-skip.md).

## Layout

```
EtudeKit/            pure engine: Tokenizer → Parser → Resolver → Model/Validator → MIDI
Tests/EtudeKitTests/ Unit · Property · Regression · Golden · Acceptance
Corpus/              vendored Mutopia .ly sources + per-file license notes
App/Etude/           SwiftUI app (Library · PieceDetail · Diagnostics) + XCUITest target
docs/adr/            Architecture Decision Records
docs/lessons/        one write-up per historical bug (symptom → root cause → guard)
PLAN.md              the phased build plan (the source of truth for what to build next)
```

`EtudeKit` imports **zero** UIKit/SwiftUI — that separation is Lesson 1 in designing for
testability (see [`docs/adr/0002-value-types-for-score.md`](docs/adr/0002-value-types-for-score.md)).

## Build & test

```sh
# Fast lane — the engine, no simulator needed:
swift test

# Slice by lesson (Swift Testing tags):
swift test --filter-tag regression

# Slow lane — app + UI tests (Xcode project is generated by XcodeGen):
cd App/Etude && xcodegen generate && \
  xcodebuild test -scheme Etude -destination 'platform=iOS Simulator,name=iPhone 17 Pro,OS=26.2'
```

## Corpus

Seven public-domain pieces: Petzold **Minuet in G**, Bach **Prelude in C** and **Air on
the G String**, Vivaldi **Largo from "Winter"**, Satie **Gymnopédie No. 1** and
**Gnossienne No. 1**, and Debussy **Clair de Lune** (the boss fight). Compositions are
public domain; vendored typesettings carry their own licenses — see
[`Corpus/LICENSES.md`](Corpus/LICENSES.md).

## How this is built

Étude is built test-first with heavy use of [Claude Code](https://claude.com/claude-code)
as the implementation tool. The method (§0 of [`PLAN.md`](PLAN.md)), the architecture, the
bug catalog, and every design decision recorded in the ADRs are the author's; the commit
discipline the history teaches is enforced on human and AI contributions alike.
